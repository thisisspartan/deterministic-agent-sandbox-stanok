# fire — терминальный факел «doom-fire» (batch + interactive)

`src/fire.py` · контракт SPEC-FIRE-2026-10-22 (C1..C11, Q6) · CC-317 (batch),
CC-318 (interactive).

Выбор режима — `sys.stdout.isatty()`:

- **batch** (не tty) — кадры как обычный текст, C6, никогда не окрашен;
- **interactive** (tty) — один экран, перерисовываемый на месте: home +
  кадр, truecolor на каждый нарисованный символ, скрытый курсор на время
  рисования, чистый выход и чистая остановка по Ctrl+C (C9..C11).

Движок (C3..C5) один и тот же: тот же seed даёт ту же сетку в обеих ветках.

## CLI (C1)

```
python3 src/fire.py --frames N [--width W] [--height H] [--seed S] [--fps F] [--no-color]
```

| Флаг | Тип | Default | Диапазон (Q6) |
|---|---|---|---|
| `--width` | int | 40 | 8..256 |
| `--height` | int | 12 | 5..120 |
| `--frames` | int | обязателен | 1..1000 |
| `--seed` | int | 0 | ≥ 0 |
| `--fps` | int | 30 | 1..60 (пауза между кадрами в interactive; в batch не используется) |
| `--no-color` | флаг | — | interactive: ноль truecolor (C10); batch никогда не красит — no-op |

`--help` → rc 0, usage в stdout (включает `--frames`, `--seed`, `--no-color`),
stderr пуст.

## Валидация (C2)

Вне диапазонов Q6, не-целое значение, отсутствующий `--frames` → rc **2**,
сообщение в stderr, stdout пуст (argparse + `_validate`).

## Детерминизм (C3)

Единственный источник случайности — `random.Random(int(--seed))` из stdlib;
порядок обращений к PRNG фиксирован (`step_heat`). Одна и та же команда с
одним seed → байт-идентичный stdout. Никакой опоры на время/окружение.

## Движок (C4)

Сетка `int[height][width]`, значения 0..255. Каждый кадр:

1. нижний ряд: каждая клетка = `rng.randint(224, 255)`;
2. распространение снизу вверх, `y` от `height-2` до 0:
   `heat[y][x] = max(0, (a+b+c)//3 − rng.randint(21,45))`, где `a,b,c` —
   `heat[y+1][x−1..x+1]`, вне сетки = 0;
3. рендер ПОСЛЕ шага (первый кадр уже показывает факел).

## Палитра (C5)

`PALETTE = " .:-=+*#%@"` (10 символов, индекс 0..9). Символ клетки =
`PALETTE[heat // 26]`; heat 0 → `' '`.

## Batch-вывод (C6)

Ровно `frames` кадров, разделитель — ровно одна пустая строка (`\n\n`);
каждый кадр — ровно `height` строк ровно по `width` символов; символы
только из PALETTE; ноль управляющих символов кроме `\n` (в batch нет
цветов); после последней строки ровно один `\n`, без завершающей пустой
строки.

## Проверяемые следствия физики (C7, C8)

- **C7:** нижняя строка каждого кадра целиком ⊆ `%@` (224..255 → индексы
  8..9), значит содержит хотя бы один горячий символ.
- **C8a (градиент):** max heat на уровне `j` над дном ≤ `255 − 21·j`,
  тепло концентрируется внизу: для кадра ≥ 2 (окно 40×15, frames 6)
  `sum_energy(нижняя треть) > 1.5 × sum_energy(верхняя треть)`, energy =
  индекс символа в PALETTE.
- **C8b (темнота):** при height 12 max heat строки 0 = `255 − 21·11 = 24 < 26`
  → индекс 0: строка 0 каждого кадра — только пробелы.

## Interactive: геометрия кадра (C9)

Один экран, перерисовываемый на месте. Порядок байтов потока:

1. старт — `ESC[?25l]` (скрыть курсор) **до** первого кадра;
2. перед каждым кадром, включая первый, — home в (0,0): `ESC[H`
   (константа `HOME`; допустимая форма `ESC[1;1H]` тоже удовлетворяет C9);
3. сам кадр — ровно `height` строк ровно по `width` символов; каждая строка
   начинается с `CRLF` (`\r\n`), то есть с начала своей строки терминала,
   независимо от того, включён ли в tty ONLCR;
4. после последней строки кадра — **ни одного** перевода строки: лишний `\n`
   при `height == rows` сдвинул бы экран (scroll);
5. выход — `ESC[0m` затем `ESC[?25h]` (курсор виден).

Никакого alt-screen (`?1049`/`?1047`/`?47`), никакого erase (`…J`), никакого
перемещения курса (`A/B/C/D`) — единственный способ нарисовать height×width
без скролла это home и запись сетки. Пробелы рисуются: каждая клетка
нарисованного ряда записывается, поэтому от предыдущего содержимого экрана
не остаётся ничего (no_residue). Следствия физики C7/C8 действуют и здесь:
нижний ряд кадра горячий, строка 0 при height 12 — пробелы.

Настройки терминала (termios) не меняются: raw-mode не берётся, Ctrl+C
обрабатывает line discipline штатным SIGINT — возвращать нечего.

## Interactive: цвет (C10)

`FIRE_COLORS` — таблица SPEC-F, индекс символа → (R, G, B); у индекса 0
(пробел) записи нет, поэтому цвет не может «придуматься» сам:

| индекс | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| RGB | 30,10,6 | 58,14,8 | 96,22,10 | 138,34,12 | 186,56,14 | 222,94,22 | 242,140,38 | 250,186,66 | 255,240,170 |

`color_sgr(ch)` возвращает `ESC[38;2;R;G;B;m` для символа палитры и `''` для
пробела; `frame_bytes(heat, color=True)` ставит этот префикс перед каждым
нарисованным не-пробельным символом. Все truecolor-triple в потоке — только
из таблицы; горячий класс (индекс 8/9) присутствует, потому что нижний ряд
горячий по C4/C7.

`--no-color` (`color=False`): ноль `ESC[38;2;…m`, геометрия та же, hide/show
курсора остаются. Естественный выход (все кадры отрисованы): `ESC[0m` затем
`ESC[?25h]` (`CLEANUP`), rc **0**.

## Interactive: Ctrl+C (C11)

SIGINT — доставлен ли он через line discipline реального PTY (настоящий
Ctrl+C) или послан процессу напрямую — прерывает цикл кадров: факел
останавливается и не рисует дальше, перед выходом пишет `ESC[0m` затем
`ESC[?25h]` в этом порядке, rc ∈ {0, 130} (здесь — 0). Обработчик SIGINT не
устанавливается и не меняется: штатный KeyboardInterrupt ловится внутри
`run_interactive`, поэтому после прерванного запуска batch-ветка работает как
обычно.

SIGTERM обработчиком не перехватывается (его штатная диспозиция и даёт
rc 143, как и рекомендует контракт); «аналогичная остановка с cleanup» —
рекомендация, не проверяемое требование: отдельного контракт-теста нет, и
обработчик, которого нет в контракте, не введён.

## API модуля

- `parse_args(argv=None) -> argparse.Namespace` — CLI + валидация (exit 2 при ошибке);
- `step_heat(heat, rng) -> None` — один шаг движка in-place;
- `render_frame(heat) -> list[str]` — кадр как строки палитры;
- `run_batch(args) -> None` — batch-рендер на stdout (C6);
- `color_sgr(char) -> str` — truecolor-SGR символа палитры, `''` для пробела (C10);
- `frame_bytes(heat, color=True) -> str` — один кадр как байты терминала: home + сетка (C9/C10);
- `interactive_stream(heats, color=True) -> str` — тот же поток как данные: hide, кадры, cleanup (без I/O и пауз);
- `run_interactive(args) -> int` — interactive-рендер на терминал, rc 0 (C9..C11);
- `main(argv=None) -> int` — точка входа, выбор ветки по `sys.stdout.isatty()`.

Константы потока: `HOME`, `HIDE_CURSOR`, `SHOW_CURSOR`, `RESET`, `CLEANUP`,
`CRLF`, таблица `FIRE_COLORS`.

Тесты: `tests/fire_test.py` и `tests/fire_interactive_test.py` (свои;
interactive — in-process, поток escape-последовательностей проверяется как
данные, без PTY), `tests/fire_contract_test.py` (accept-оракул C1..C8) и
`tests/fire_terminal_test.py` (accept-оракул C9..C11: реальный PTY, судья
`tests/fixtures/vt_screen.py`, Ctrl+C настоящим нажатием).
