# fire — цветное пламя в консоли (tickets TASK-STANOK-CC-030..036)

Бесконечная анимация пламени в стиле камина: пламя — язык, широкий у
основания и сужающийся кверху; источник — центральная зона низа; пламя
«дышит» (медленная модуляция интенсивности); сверху летят искры (только
из центральной зоны). Пламя горит ВНУТРИ камина: статичная кирпичная
рамка по периметру и тёмный фон окна (ticket 032). Брёвен/дров внутри
НЕТ — только 2D-рамка. Работает вечно до выхода.

## Камин (ticket 032)

- **Рамка** — статична (не зависит от state/heat, детерминирована):
  символы кирпич/камень `▓ █ ▒`, цвета ТОЛЬКО из тёмной палитры
  `{24, 25, 26, 27, 58}` (ticket 033 F1 — цвета 236–239 запрещены).
  Конструкция: подиум снизу (2 ряда кирпичей на всю ширину), перемычка
  сверху (2 ряда), боковые стойки (2 колонки слева и справа). При узких
  сетках (H≤4 или W≤8) толщина падает до 1 ряда/колонки.
- **Тёмный фон окна** — ячейки окна с heat=0 рендерятся цветом 234
  (дип-серый, диапазон 233–235), а не пустым пробелом: огонь горит «в
  темноте». Вне камина ничего не рисуется.
- **Брёвен/палок/дров внутри камина нет.**

## Запуск

```sh
node src/fire/main.js
```

- **TTY (интерактивно)**: raw mode, альтернативный экран (`\x1b[?1049h`),
  курсор скрыт; полный перерисовочный кадр каждые ~33 мс (~30 FPS).
- **Non-TTY** (pipe/CI): рендерятся 10 фиксированных кадров в stdout,
  `exit(0)` — программа не вешается без терминала.

## Управление (выход)

| Клавиша      | Действие                     |
|--------------|------------------------------|
| `q` / `Q`    | чистый выход                 |
| `ESC`        | чистый выход                 |
| `Ctrl+C`     | чистый выход (или SIGINT)    |

При остановке (любой причиной, включая ошибку) ВСЕГДА восстанавливается
терминал: курсор показывается (`\x1b[?25h`) и альтернативный экран
закрывается (`\x1b[?1049l`).

## Параметры

`createFire(opts)` / `attach(io, fire, opts)` (все необязательны):

| Параметр      | Дефолт          | Смысл                                   |
|---------------|-----------------|-----------------------------------------|
| `W`           | `80`            | ширина сетки (столбцов)                 |
| `H`           | `24`            | высота сетки (рядов)                    |
| `seed`        | `1`             | зерно PRNG (детерминизм)                |
| `rng`         | `mulberry32(seed)` | инжектируемый PRNG, функции `[0,1)`  |
| `decay`       | `0.96`          | затухание тепла вверх (0.85…0.96)       |
| `sparks`      | `16`            | число частиц-искр                       |
| `fpsMs`       | `33`            | период кадра UI (~30 FPS)               |

Детерминизм: один `seed` → идентичные кадры (тепло и искры) при
пошаговом прогоне; `opts.rng` позволяет заменить PRNG целиком.

## Физика (src/fire/fire.js)

- Сетка `W×H` температур `heat[y][x] ∈ [0..1]`, источник тепла — ЦЕНТРАЛЬНАЯ
  ЗОНА нижнего ряда (средние 50% ширины, `SOURCE_HALF = 0.25`): косинусный
  профиль по X задаёт MASK (1.0 в центре → 0 к краям зоны), вне зоны — 0;
  базовая температура `BASE_FLOOR = 0.9` + **per-cell flicker** (ticket 033 F2):
  каждая ячейка источника каждый шаг получает собственный шум
  `fl = FLICKER_LOW + FLICKER_HIGH * rng()` (диапазон [-0.25, +0.25));
  итог `b[x] = mask[x] * (BASE_FLOOR + fl) * breath` — соседние ячейки
  различаются резко, а не косинусно (max-min по ряду источника ≥ 0.3,
  max|b[x]-b[x-1]| ≥ 0.15).
- Шаг симуляции снизу вверх (ticket 033 F3 — усиленное распространение):
  `heat[y][x] = avg3x3(heat[y+1..y+2][x-1..x+1]) * decay * taper(y)
  + noise*sparkle`, `decay ≈ 0.85..0.96` (дефолт `0.96`).
  Средн. по 3×3 (ряд y+1 вес ×2, ряд y+2 вес ×1 по центральной колонке)
  даёт вертикальную диффузию — пламя поднимается ≥ 12 рядов от основания
  (heat > 0.3), сохраняя taper (сужение кверху).
- Сужение кверху (F2): `taper(y) = 1 - ((H-1-y)/H)^k * TAPER_MAX`
  (`TAPER_K = 2`, `TAPER_MAX = 0.6`) — верхние ряды заметно холоднее,
  пламя сужается кверху, как язык.
- Полыхание / «дыхание» (F3): низкочастотный синус
  `breath = 1 - AMP * (0.5 + 0.5*sin(2π·frame / PERIOD))`
  (`PERIOD = 60` кадров ≈ 2 с при 30 FPS, `AMP = 0.15`, т.е. ±15%)
  модулирует интенсивность источника; детерминировано счётчиком кадров —
  один seed → те же кадры.
- Искры: N частиц `{x, y, vy, life}` — поднимаются (`vy < 0`), затухают
  (`life` убывает), при `life <= 0` или вылете за верх возрождаются
  ТОЛЬКО в центральной зоне источника (x ∈ [W/4, 3W/4]); дрейф по X
  зажимается внутри той же зоны.

## Жизненный цикл огня (ticket 035)

Огонь не горит вечно на одной интенсивности — внутри `step()` живёт
детерминированная (PRNG, по счётчику step'ов при 30 FPS, а не по wall-clock)
машина состояний. Порядок фиксирован и зациклен:
**BURN → DIE → EMBER → REKINDLE → BURN → …**

| Фаза       | Длительность (step'ов) | Мультипликатор источника |
|------------|------------------------|--------------------------|
| BURN       | `BURN_STEPS = 1500` (~50 с) | `1.0` — полное пламя, как раньше |
| DIE        | `DIE_STEPS = 360` (~12 с)   | линейно `1.0 → DIE_MIN = 0.15`; пламя сжимается к основанию (верх гаснет первым — из-за decay) |
| EMBER      | `EMBER_STEPS = 240` (~8 с)  | `0` — источник выключен |
| REKINDLE   | `REKINDLE_STEPS = 240` (~8 с) | smoothstep `0 → 1.0` — «вспых» и возврат в BURN |

Мультипликатор умножается на весь ряд источника
(`b[x] = mask*(BASE_FLOOR+flicker)*breath*mult`) — физика без хардкода фаз.

**Угли (EMBER).** Источник ≈ 0, но в основании окна (2 ряда над plinth,
ряды `base-2`/`base-3`) тлеют **угли**: при входе в EMBER через PRNG
выбирается фиксированное подмножество ячеек (`EMBER_COUNT = 6`) из зоны
источника. Каждая углей — медленный синус (период `EMBER_FLICK_PERIOD = 8`,
длиннее мерцания пламени) амплитудой `EMBER_FLICK_AMP = 0.05` + малый
покадровый джиттер; базовое тепло `[0.12 .. 0.24]` (диапазон heat 0.05–0.3).
Между кадрами их тепло меняется (мерцание), но max(heat) окна остаётся < 0.4.

**Искры в слабых фазах.** Искра возрождается только если `mult >= 0.3`
(`SPARK_SOURCE_MIN`) — в EMBER и позднем DIE искры физически не вспыхивают
(паркуются в ряду plinth, где render их не рисует) и оживают сами при
разгорании. Это следует из физического мультипликатора, а не из имени фазы.

**Детерминизм.** Переходы — только по счётчику step'ов, всё на том же
mulberry32(seed): тот же seed → идентичная последовательность кадров, включая
фазы цикла. Non-TTY режим (10 кадров) = начало BURN, ничего не ломает.
Рендер (глифы плотности, рамка, цвет) — без изменений.

## Глифы плотности пламени (tickets 034, 036)

В терминале без 256-цветов пламя не должно исчезать: каждая ячейка окна
(НЕ рамка) получает глиф из строки-рампы `FLAME_GLYPHS = " .,;:~*oO@"`
(не менять) по формуле `flameGlyphIndex(heat)`:

- `FLAME_MIN = 0.08` — порог: `heat <= FLAME_MIN` → индекс `0` (глиф ` `,
  фон окна, цвет остаётся `234`).
- `FLAME_MIN < heat <= 1` → индекс ∈ `[1, len-1]`, монотонный по heat и
  непрерывный слева в точке FLAME_MIN:
  `i = clamp(round((heat - FLAME_MIN) / (1 - FLAME_MIN) * (len - 1)), 1, len - 1)`.
  Максимум heat → самый тяжёлый глиф `@` (индекс `len-1`).
- **Фикс разрыва (ticket 036).** Старая формула `floor(heat * (len-1))`
  рендерила весь диапазон `heat ∈ (FLAME_MIN, 1/9) ≈ (0.08, 0.111)` как
  ПРОБЕЛ, хотя heat > FLAME_MIN. Угли живут в heat ≈ 0.05–0.24 → весь
  EMBER-кадр был пустым окном («чуть проигрывается и всё»). Новая формула
  гарантирует: любой `heat > FLAME_MIN` — непустой глиф. BURN в верхней
  части диапазона визуально не меняется: ядро (heat≈1) — тот же `@`, верх
  пламени (низкий heat) стал чуть плотнее — это и есть фикс разрыва.
- **Видимость углей.** Мерцающие угли EMBER (heat ≈ 0.05–0.24) теперь
  видны как точки/тире (`.,;:`) на тёмном фоне окна: ≥5 ячеек окна с
  непустым глифом в типичном EMBER-кадре (тест `tests/fire/ember.test.js` E3).
- Цвет-код `38;5;NNN` (из `colorIndex`) идёт вместе с глифом: терминал
  с цветами показывает цветное пламя, без — ASCII-форму.
- Рампа избегает кирпичных глифов (`▓█▒`), искр (`✦`) и символов брёвен
  (`=`, `#`, `-`), запрещённых тестом R3.
- **Экспорты для тестов (ticket 036):** из `src/fire/fire.js` дополнительно
  экспортируются `flameGlyphIndex`, `FLAME_GLYPHS`, `FLAME_MIN` и константы
  цикла фаз `PHASE_BURN/PHASE_DIE/PHASE_EMBER/PHASE_REKINDLE`,
  `BURN_STEPS/DIE_STEPS/EMBER_STEPS/REKINDLE_STEPS` — тесты детерминированно
  доходят до нужной фазы без хардкода счётчиков. Сигнатуры
  `createFire/render/colorIndex/mulberry32` — не менялись.

## Палитра (render)

Температура → 256-цветные коды `\x1b[38;5;Nm`, линейные интерполяции по
ступеням xterm-256: `0` → тёмный фон окна (234, если ячейка внутри камина);
затем тлеющий тёмно-красный край (160) → красный (196) → оранжевый
(202/214) → жёлтый (226) → горячее ядро белый (231). Искры рендерятся
поверх пламени яркими пикселями `✦` (в клетках рамки искры не рисуются).
Вне камина (рамка) — кирпичи `▓ █ ▒` в тёмной палитре `{24, 25, 26, 27, 58}`
(цвета 236–239 нигде не используются), статично.
`render(state, width) → string` — ЧИСТАЯ функция: кадр одним строковым
блоком (курсор в начало `\x1b[H`, H строк, очистка хвоста `\x1b[J`); `width`
обрезает колонки на узких терминалах; тот же state → тот же кадр.
