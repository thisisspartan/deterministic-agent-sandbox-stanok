# fire — терминальный факел «doom-fire» (batch-режим)

`src/fire.py` · контракт SPEC-FIRE-2026-10-22 (C1..C8, Q6) · CC-317.

Интерактивный (TTY) режим — следующий тикет; здесь реализована только
batch-ветка. Выбор режима — `sys.stdout.isatty()`; пока TTY-ветки нет,
обе ветки выводят детерминированный batch.

## CLI (C1)

```
python3 src/fire.py --frames N [--width W] [--height H] [--seed S] [--fps F] [--no-color]
```

| Флаг | Тип | Default | Диапазон (Q6) |
|---|---|---|---|
| `--width` | int | 40 | 8..256 |
| `--height` | int | 12 | 5..120 |
| `--frames` | int | обязателен | 1..1000 |
| `--seed` | int | 0 | ≥ 0 |
| `--fps` | int | 30 | 1..60 (в batch не используется) |
| `--no-color` | флаг | — | batch никогда не красит — флаг no-op |

`--help` → rc 0, usage в stdout (включает `--frames`, `--seed`, `--no-color`),
stderr пуст.

## Валидация (C2)

Вне диапазонов Q6, не-целое значение, отсутствующий `--frames` → rc **2**,
сообщение в stderr, stdout пуст (argparse + `_validate`).

## Детерминизм (C3)

Единственный источник случайности — `random.Random(int(--seed))` из stdlib;
порядок обращений к PRNG фиксирован (`step_heat`). Одна и та же команда с
одним seed → байт-идентичный stdout. Никакой опоры на время/окружение.

## Движок (C4)

Сетка `int[height][width]`, значения 0..255. Каждый кадр:

1. нижний ряд: каждая клетка = `rng.randint(224, 255)`;
2. распространение снизу вверх, `y` от `height-2` до 0:
   `heat[y][x] = max(0, (a+b+c)//3 − rng.randint(21,45))`, где `a,b,c` —
   `heat[y+1][x−1..x+1]`, вне сетки = 0;
3. рендер ПОСЛЕ шага (первый кадр уже показывает факел).

## Палитра (C5)

`PALETTE = " .:-=+*#%@"` (10 символов, индекс 0..9). Символ клетки =
`PALETTE[heat // 26]`; heat 0 → `' '`.

## Batch-вывод (C6)

Ровно `frames` кадров, разделитель — ровно одна пустая строка (`\n\n`);
каждый кадр — ровно `height` строк ровно по `width` символов; символы
только из PALETTE; ноль управляющих символов кроме `\n` (в batch нет
цветов); после последней строки ровно один `\n`, без завершающей пустой
строки.

## Проверяемые следствия физики (C7, C8)

- **C7:** нижняя строка каждого кадра целиком ⊆ `%@` (224..255 → индексы
  8..9), значит содержит хотя бы один горячий символ.
- **C8a (градиент):** max heat на уровне `j` над дном ≤ `255 − 21·j`,
  тепло концентрируется внизу: для кадра ≥ 2 (окно 40×15, frames 6)
  `sum_energy(нижняя треть) > 1.5 × sum_energy(верхняя треть)`, energy =
  индекс символа в PALETTE.
- **C8b (темнота):** при height 12 max heat строки 0 = `255 − 21·11 = 24 < 26`
  → индекс 0: строка 0 каждого кадра — только пробелы.

## API модуля

- `parse_args(argv=None) -> argparse.Namespace` — CLI + валидация (exit 2 при ошибке);
- `step_heat(heat, rng) -> None` — один шаг движка in-place;
- `render_frame(heat) -> list[str]` — кадр как строки палитры;
- `run_batch(args) -> None` — batch-рендер на stdout (C6);
- `main(argv=None) -> int` — точка входа.
